## Entity Definitions

### 1. User (Existing Entity - Extended)

**Description**: Represents an authenticated user in the application. Extended with admin role flag for chronicle permissions.

**Attributes**:

| Field      | Type      | Required | Constraints                 | Description                              |
| ---------- | --------- | -------- | --------------------------- | ---------------------------------------- |
| `UserId`   | `number`  | ✅       | Primary key, auto-increment | Unique user identifier                   |
| `Username` | `string`  | ✅       | Unique, alphanumeric        | User's login name                        |
| `Alias`    | `string`  | ✅       | Max 50 chars                | Display name                             |
| `IsAdmin`  | `boolean` | ✅       | Default: `false`            | Admin role flag for chronicle management |

**Relationships**:

- **Creates** → `ChronicleEntry` (1:N) - One user creates many chronicle entries
- **Creates** → `ChronicleComment` (1:N) - One user creates many comments
- **Edits** → `ChronicleEntry` (1:N, optional) - Admin edits entries
- **Edits** → `ChronicleComment` (1:N, optional) - Admin/creator edits comments

**Notes**:

- Existing entity in database; requires adding `IsAdmin` column (or read from JWT token claim)
- Alias is used for display in chronicle/comments UI

---

### 2. ChronicleEntry

**Description**: Represents a news/announcement post on the start page. Createable and editable by administrators.

**Attributes**:

| Field            | Type     | Required | Constraints                         | Description                                   |
| ---------------- | -------- | -------- | ----------------------------------- | --------------------------------------------- |
| `Id`             | `number` | ✅       | Primary key, auto-increment         | Unique chronicle entry identifier             |
| `Title`          | `string` | ✅       | Max 200 chars, non-empty            | Entry headline                                |
| `Content`        | `string` | ✅       | Max 5000 chars, HTML format         | Rich text content (sanitized HTML)            |
| `AuthorId`       | `number` | ✅       | Foreign key → User.UserId           | Creator of the entry (admin)                  |
| `CreatedDate`    | `string` | ✅       | ISO 8601 format                     | Timestamp when entry was created              |
| `LastEditedDate` | `string` | ❌       | ISO 8601 format, nullable           | Timestamp of last edit (null if never edited) |
| `EditedById`     | `number` | ❌       | Foreign key → User.UserId, nullable | User who last edited (null if never edited)   |

**Validation Rules**:

- `Title`: Min 1 char, max 200 chars, must not be blank/whitespace-only
- `Content`: Min 1 char, max 5000 chars, must pass HTML sanitization
- `Content` allowed HTML: `<p>`, `<strong>`, `<em>`, `<a>`, `<ul>`, `<ol>`, `<li>`, `<h1>`, `<h2>`, `<h3>`, `<br>`
- `AuthorId`: Must exist in User table and have `IsAdmin = true`
- `CreatedDate`: Auto-generated by backend on creation
- `LastEditedDate`: Auto-updated by backend on edit
- `EditedById`: Set to current user's ID on edit

**Relationships**:

- **Created by** → `User` (N:1) - Many entries created by one admin
- **Edited by** → `User` (N:1, optional) - Many entries edited by one admin
- **Has** → `ChronicleComment` (1:N) - One entry has many comments

**State Transitions**:

1. **Created**: `Id`, `Title`, `Content`, `AuthorId`, `CreatedDate` are set; `LastEditedDate` and `EditedById` are `null`
2. **Edited**: `Title` and/or `Content` updated; `LastEditedDate` and `EditedById` are set
3. **Deleted**: Entry removed; all associated comments are cascade-deleted

**Indexes** (for query performance):

- Primary: `Id`
- Index: `CreatedDate DESC` (for sorting newest first)
- Foreign key: `AuthorId`, `EditedById`

### 3. ChronicleComment

**Description**: User comment on a chronicle entry. Editable by creator or admin.

**Attributes**:

| Field              | Type     | Required | Constraints                         | Description                                   |
| ------------------ | -------- | -------- | ----------------------------------- | --------------------------------------------- |
| `Id`               | `number` | ✅       | Primary key, auto-increment         | Unique comment identifier                     |
| `Text`             | `string` | ✅       | Max 500 chars, plain text           | Comment content (no HTML)                     |
| `AuthorId`         | `number` | ✅       | Foreign key → User.UserId           | Commenter (any authenticated user)            |
| `ChronicleEntryId` | `number` | ✅       | Foreign key → ChronicleEntry.Id     | Parent chronicle entry                        |
| `CreatedDate`      | `string` | ✅       | ISO 8601 format                     | Timestamp when comment was posted             |
| `LastEditedDate`   | `string` | ❌       | ISO 8601 format, nullable           | Timestamp of last edit (null if never edited) |
| `EditedById`       | `number` | ❌       | Foreign key → User.UserId, nullable | User who last edited (for admin edits)        |

**Validation Rules**:

- `Text`: Min 1 char, max 500 chars, must not be blank/whitespace-only
- `Text`: Plain text only (HTML stripped via DOMPurify)
- `AuthorId`: Must exist in User table
- `ChronicleEntryId`: Must exist in ChronicleEntry table
- `CreatedDate`: Auto-generated by backend on creation
- `LastEditedDate`: Auto-updated by backend on edit
- `EditedById`: Set to current user's ID on edit (shows admin attribution if different from AuthorId)

**Relationships**:

- **Created by** → `User` (N:1) - Many comments by one user
- **Edited by** → `User` (N:1, optional) - Comment edited by creator or admin
- **Belongs to** → `ChronicleEntry` (N:1) - Many comments on one entry

**State Transitions**:

1. **Created**: `Id`, `Text`, `AuthorId`, `ChronicleEntryId`, `CreatedDate` are set; `LastEditedDate` and `EditedById` are `null`
2. **Edited by Creator**: `Text` updated; `LastEditedDate` set; `EditedById` = `AuthorId`
3. **Edited by Admin**: `Text` updated; `LastEditedDate` set; `EditedById` = admin's UserId (different from `AuthorId`)

**Cascade Delete**: When parent `ChronicleEntry` is deleted, all associated comments are deleted.

**Indexes** (for query performance):

- Primary: `Id`
- Index: `ChronicleEntryId, CreatedDate ASC` (for fetching comments in chronological order)
- Foreign key: `AuthorId`, `ChronicleEntryId`, `EditedById`

## Database Schema (Backend Reference)

**Note**: This is a reference for backend implementation (out of scope for frontend plan). Included for completeness.

### ChronicleEntries Table

```sql
CREATE TABLE ChronicleEntries (
    Id INT PRIMARY KEY IDENTITY(1,1),
    Title NVARCHAR(200) NOT NULL,
    Content NVARCHAR(MAX) NOT NULL, -- HTML content, max 5000 chars enforced in app
    AuthorId INT NOT NULL FOREIGN KEY REFERENCES Users(UserId),
    CreatedDate DATETIME2 NOT NULL DEFAULT GETUTCDATE(),
    LastEditedDate DATETIME2 NULL,
    EditedById INT NULL FOREIGN KEY REFERENCES Users(UserId),
    INDEX IX_CreatedDate (CreatedDate DESC)
);
```

### ChronicleComments Table

```sql
CREATE TABLE ChronicleComments (
    Id INT PRIMARY KEY IDENTITY(1,1),
    Text NVARCHAR(500) NOT NULL, -- Plain text
    AuthorId INT NOT NULL FOREIGN KEY REFERENCES Users(UserId),
    ChronicleEntryId INT NOT NULL FOREIGN KEY REFERENCES ChronicleEntries(Id) ON DELETE CASCADE,
    CreatedDate DATETIME2 NOT NULL DEFAULT GETUTCDATE(),
    LastEditedDate DATETIME2 NULL,
    EditedById INT NULL FOREIGN KEY REFERENCES Users(UserId),
    INDEX IX_EntryComments (ChronicleEntryId, CreatedDate ASC)
);
```

## Security Considerations

1. **XSS Prevention**:
   - Chronicle content: Sanitize HTML with DOMPurify (allowed tags only)
   - Comment text: Strip all HTML (plain text only)

2. **Authorization**:
   - Only admins can create/edit/delete chronicle entries (check `IsAdmin` claim in JWT)
   - Only comment author or admin can edit comments (check `AuthorId` or `IsAdmin`)

3. **Input Validation**:
   - Frontend: Client-side validation for UX (immediate feedback)
   - Backend: Server-side validation for security (never trust client)

4. **SQL Injection**:
   - Backend uses parameterized queries (ORM/Entity Framework)

5. **Rate Limiting**:
   - Backend implements rate limiting on POST endpoints to prevent spam
